# 交互规则

## 多动作推送选项机制

当存在多个待执行的后续动作（≥2个）时，不要让用户手动逐个敲指令，而是用 `AskUserQuestion` 工具主动推送选项让用户批量确认。

### 触发条件
- 任务完成后有 ≥2 个可选的后续动作
- 分析报告输出后，有多个落盘/记录/下一步动作
- 评审/检查后，有多个修改项需要确认

### 使用方式
用 `AskUserQuestion` 给出选项，让用户多选或单选确认要执行的动作。

### 示例
```
# 分析报告输出后，有3个待执行动作
AskUserQuestion:
  question: "接下来要执行哪些动作？"
  multiSelect: true
  options:
    - "记录踩坑到 lessons-learned.md"
    - "落盘分析到 docs/requirements/"
    - "标记一期用例作废点"
    - "直接开始写二期用例"
```

### 禁止
- ❌ 不要在只有一个动作时强行推送选项
- ❌ 不要在用户已明确给出指令时再问一遍
- ❌ 不要把纯确认性动作（如"是否继续？"）做成选项
