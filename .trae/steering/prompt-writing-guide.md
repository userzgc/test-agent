# Prompt 写作规范

写给 LLM 的所有文本（Agent 指令、Steering、Skill）都应遵循：

## 5 条核心规则

### 1. 去噪
删掉不改变语义的词。
- ❌ "请你帮我分析一下这个需求" → ✅ "分析需求"
- ❌ "接下来我们来进行下一步操作" → ✅ "下一步："

### 2. 结构化优于叙述
- 用表格替代段落
- 用示例替代解释
- 用列表替代长句

### 3. 一个概念只出现一次
用 `#[[file:xxx]]` 或"见 `skill-name`"引用，不复制粘贴。
- ❌ 把 Skill 的内容复制到 Agent Prompt（70% 重复，维护成本翻倍）
- ✅ Prompt 中写 `操作规范见 #skill-name`

### 4. 约束前置，示例后置
模型对开头的注意力权重更高。
- 先写禁止/约束规则，再写正确示例
- 先写核心原则，再写具体步骤

### 5. 引用文件时只引关键片段
超过 200 行的文件说明需要哪个章节。
- ❌ "详见 agent.md"
- ✅ "详见 `agent.md` 的「工作流」章节（第 15-22 行）"

## Agent vs Skill 内容判断

| 写什么 | 放哪里 | 判断标准 |
|--------|--------|---------|
| 你是谁、做什么顺序、什么时候停 | Agent Prompt | 换一个业务场景还能用吗？不能 → Agent |
| 怎么做（操作规范、格式模板、踩坑规避） | Skill | 换一个业务场景还能用吗？能 → Skill |

**反面教材**：把 Skill 的内容复制到 Agent Prompt，导致 70% 重复，维护成本翻倍。

**正确做法**：Prompt 中写 `操作规范见 #skill-name`。

## 格式偏好

| 场景 | 推荐 | 不推荐 |
|------|------|--------|
| 规则列表 | 表格 | 段落 |
| 步骤说明 | 有序列表 | 段落 |
| 命令模板 | 代码块 | 行内代码 |
| 条件判断 | 表格 | if-else 段落 |
| 对比 | 表格 | 并列段落 |
