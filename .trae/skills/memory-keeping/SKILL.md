# 记忆沉淀

## 背景与硬约束

IDE 的聊天记录会被清除，且 **Hook 无法感知对话内容**（`on-stop-check-lessons.sh` 里已注明并验证）。所以记忆**不可能**做成"自动全量录音"，只能是：

- **Agent 主动落盘** —— 判断有价值 → 写入 `docs/memory/`
- **Hook 负责提醒和加载** —— SessionStart 加载索引，Stop 提醒自查

## 三层记忆分工（不要混）

| 记忆类型 | 落在哪 | 内容 |
|---------|--------|------|
| 踩坑 / 根因 / 修复 | `docs/lessons-learned.md` | 我们做错了什么，怎么避免 |
| **业务口径 / 判定规则** | `docs/memory/decisions.md` | 业务是什么，下次同类需求直接复用 |
| **关键会话存档** | `docs/memory/sessions/YYYY-MM-DD_主题.md` | 澄清过程、被纠正的理解 |
| 索引 | `docs/memory/index.md` | 一行一条，供 SessionStart 加载 |

## 什么该记

**必须记**：

- 需求方**口述澄清**的业务口径（文档里没写、只在对话里说过的）→ `decisions.md`
- 聚合 / 边界 / 降级这类"实现容易做反"的口径 → `decisions.md`，且单列「关键实现分歧点」
- 我的理解**被用户纠正过** → `sessions/`，写清错在哪、正确是什么
- 已登记但**未闭环**的待确认问题 → `decisions.md` 的「待确认」段
- 发现的产品风险 / 缺陷线索 → `decisions.md` 的「已登记风险」段

**不要记**：

- 需求文档里已写清楚的内容（写来源引用即可，别复制原文）
- 一次性的调试过程、闲聊、探索性提问
- 已在 `lessons-learned.md` 记过的踩坑（不重复记）

## 写入时机

1. **用户说触发词**：`记一下 / 存档 / 记住这个 / 沉淀一下` → 立即写入并告知落在哪
2. **Stop Hook 提醒时自查**：本次会话有无口述澄清的业务口径、有无被纠正的理解 → 有则写入并简要告知
3. **一个需求的对齐阶段结束时**：把该需求确认的全部口径整理成一节写入 `decisions.md`

## 格式

### `decisions.md` — 每个需求一节

```markdown
## <需求名> — <口径主题>

- **来源**：文档链接 / pageId / 版本
- **确认日期**：YYYY-MM-DD
- **确认方式**：需求方口述 / 文档明确 / 技术评审
- **适用范围**：哪个系统的哪个模块

### <分类小节，如 生效范围 / 配置端 / C端判定 / 状态与时序>
1. 一条一个口径，编号在本节内连续，加粗关键差异词

### 待确认（截至 YYYY-MM-DD 未闭环）
### 已登记的产品风险
### 关键实现分歧点（交付时重点盯）
```

### `index.md` — 一行一条

```
| YYYY-MM-DD | 主题 | 类型 | 一句话关键结论 | 文件链接 |
```

## 复用规则（记忆的价值全在这一步）

新需求分析启动时：

1. 先看 `docs/memory/index.md` 有无同类需求
2. 有 → 读对应 `decisions.md` 段落，**已确认的口径不要再问用户一遍**
3. 引用记忆里的口径时，标注"来自 &lt;日期&gt; 确认"，并提示用户确认是否仍然有效 —— 业务口径会变，不能当永久事实用

## 禁止

- ❌ 把记忆当成对话逐字稿，大段复制原文
- ❌ 同一条口径在 `decisions.md` 和 `lessons-learned.md` 各写一份
- ❌ 直接拿记忆里的口径当事实用，却不告知用户来源和日期
- ❌ 每次会话都写一条，把索引淹没在噪声里
