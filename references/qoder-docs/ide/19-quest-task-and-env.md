# Quest 任务管理 与 执行环境（Qoder IDE）

> 来源：/zh/user-guide/quest/task-management + /zh/user-guide/quest/execution-environments

## 创建任务的四项配置

点击左侧任务列表顶部 **创建 Quest**：

| 配置 | 选项 |
|---|---|
| **模式** | **Agent**（端到端自主编程，单智能体：澄清需求→规划→执行→验证。适合功能开发、原型验证、工具搭建）/ **Experts**（多智能体协作，Team Lead 自动拆解并组建专家团队，前端/后端/QA/代码评审**并行执行互不等待**。适合全栈开发、复杂问题定位、技术方案调研） |
| **分支管理** | 为任务创建并切换 Git 分支，隔离不同任务的代码变更 |
| **执行环境** | Local / Worktree |
| **Spec 驱动** | 启用后先生成结构化 Spec（**需求描述、设计方案、任务拆分、验收标准**），确认后再执行 |

## 分组、排序与筛选

左侧 Quests 列表顶部筛选图标：
- **分组**：默认按「工作区」
- **排序**：默认按「已更新」
- **筛选**：按「状态」「已读状态」「归档」，默认「全部」
- **重置**：一键恢复默认

## 生命周期四状态

| 状态 | 说明 |
|---|---|
| **Running** | Agent 正在执行中 |
| **Action Required** | **等待用户确认或输入** |
| **Ready** | 任务已完成，可继续对话迭代 |
| **Error** | 执行过程中发生错误 |

**暂停/恢复**：Pause / Resume。
**追加需求**：执行过程中直接在输入框发送新需求，Quest 会调整计划并继续。

## ⭐ Fork 会话

会话更多按钮 → **Fork** → 从当前会话创建一条独立新会话。
**继承原会话全部上下文和历史消息，但后续对话彼此独立互不影响。**

适用：
- 基于同一段讨论**尝试不同方案**
- 把当前任务**拆成多条独立线并行推进**
- Quest 任务中可**从任意一轮对话处发起 Fork**，创建新任务分支继续追问

（Editor 视窗中的会话完成后同样支持 Fork。）

> 🎯 对本项目直接可用：讨论到「方案 A vs 方案 B」这种分叉点时，
> Fork 两条线各自推进，比在一条会话里来回切换清楚得多。

## 执行环境

| 环境 | 说明 | 适用 |
|---|---|---|
| **Local** | 在当前工作区直接改代码，变更落在当前项目目录 | 小改动、快速验证 |
| **Worktree** | 用独立的 **Git worktree** 检出，与主分支工作区隔离，确认后再合并或应用 | 中等复杂度、多次应用、**同一仓库并行多任务** |

（并行任务数在套餐与配额允许范围内。）

### Worktree 适用场景

| 场景 | 说明 |
|---|---|
| **并行多任务** | 同时处理多个需求或重构，每条线独立推进 |
| **高风险重构** | 让 Agent 大胆尝试架构调整或大规模重命名，**不满意直接丢弃，主工作区毫发无损** |

### 使用步骤

1. 聊天面板顶部运行环境区域，点击当前模式（如「本地模式」）
2. 下拉中选 **Worktree**
3. 在模式选择器旁的**分支下拉**中选择基于哪条本地分支创建工作树
4. 输入任务描述发送

> 主工作区有未提交改动时，面板显示「**包含未提交变更**」开关。
> 开启后创建时会把这些改动同步到工作树，确保 Agent 看到最新代码状态。

### 移交到本地

工作树中完成后，左侧任务列表找到对应会话 → 「**移交到本地**」，
把 worktree 的分支状态和未提交改动移交到主工作区，后续任务在本地继续。

> ⚠️ **移交前本地工作区必须干净（无未提交变更）**，建议先 commit 或 stash。

### 直接在工作树中提交

不需要带回本地时：会话右侧打开「审查与提交」面板 → 确认变更 → **创建新分支并提交**。

### 初始化脚本

设置中找「**本地任务的 Worktree 配置**」，编辑启动脚本，
创建 Worktree 时自动执行初始化（安装依赖、复制环境变量文件等）。

### 清理

- **自动**：系统自动清理较早的工作树。管理面板底部配置「**最大保留数**」，每个工作区**默认 15 个**
- **手动**：左侧会话列表对工作树会话「删除」会一并删除工作树；也可在设置中统一管理

### 注意事项

- **必须是 Git 仓库**，Worktree 选项才出现
- 移交前保持工作区干净
- **磁盘占用**：每个工作树是独立文件检出，项目大时多个工作树占用可观空间

> 🎯 对本项目：批量重构用例资产（例如把 53 条用例统一改格式）时用 Worktree，
> 失败直接丢弃。这和 CLI 内置的 `batch` skill 是同一思路（见 `cli/12-builtins.md`）。
