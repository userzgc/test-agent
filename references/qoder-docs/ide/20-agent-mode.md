# Agent 模式（Qoder IDE 智能体模式）

> 来源：https://docs.qoder.com/zh/user-guide/chat/agent

智能体模式具备自主决策、环境感知与工具调度能力，可用项目搜索、文件编辑、终端访问等工具完成编码任务。

## 五项核心能力

| 能力 | 说明 |
|---|---|
| **项目级更改** | 自主拆解任务、修改多个文件；多轮对话可优化或**快照回滚** |
| **计划制定** | 创建分步计划供审阅 |
| **自动环境感知** | 从任务描述中自动检测项目框架、技术栈、所需文件及错误信息，**无需手动补充 context** |
| **工具使用** | 自主使用内置工具，也支持自动发现并使用 MCP 工具 |
| **命令执行** | 自主决定要执行的命令并在终端生成运行 |

## 规划

Agent 根据自主意图识别，针对复杂任务自动生成方案和规划，展示给用户审阅，确认后按规划执行。

> 官方提示：**需要严格对齐技术方案或包含复杂步骤的中大型任务，
> 推荐用 Quest 工作区的 Spec 驱动模式**，在写代码前先生成结构化设计文档。

## 待办事项

生成含待办事项的计划供审阅，把复杂问题拆成可管理、按顺序执行的步骤。
想加步骤只需补充需求，Qoder 会把对应待办加进计划。

聊天窗口底部进度标识：
- **空心圆圈** = 未开始
- **旋转圆圈** = 进行中
- **复选框** = 已完成

## 多文件编辑的三个状态

| 状态 | 含义 |
|---|---|
| **正在生成** | 基于任务拆解生成代码建议 |
| **正在应用** | 将建议与原始文件集成，生成变更文件 |
| **已应用** | 变更已完成，**等待审阅** |

点击文件可查看建议生成过程和 diff。

## 审阅、接受或拒绝

点击 **查看变更**：
- 上下箭头在当前文件内导航变更
- **针对每处变更**单独接受或拒绝
- 文件级操作区的前进/后退箭头在变更文件间切换
- 文件级操作区**批量**接受或拒绝
- 可对变更文件做**部分修改**

## 多轮迭代与 Revert

完成当前会话并生成变更后，可继续提交补充查询完善需求 ——
Qoder 会**合并先前的代码变更**，分析更新后的需求，生成新的变更文件。

> ⭐ **撤销当前会话产生的全部代码变更**：点对话流中的 **Revert** 按钮，触发自动回滚。

## 执行命令

默认**每条命令执行前需确认**：
- **执行** → 提交并运行
- **取消** → 跳过该命令，按指示进行下一步

后台运行的任务显示「在后台执行」指示器，Agent 继续处理其他任务，需要时回来检查输出。

### ⭐ 自动执行命令允许列表

**Qoder IDE 设置**（用户图标或 `⌘⇧,` / `Ctrl+Shift+,`）→ **智能会话** → 配置允许列表。
**多个命令用逗号分隔。**

> 🎯 对本项目：`.trae/scripts/` 里那些 Python 脚本（XMind 处理等）如果每次都要点确认，
> 把它们加进允许列表能省掉大量交互。这是 IDE 侧的等价物，
> CLI 侧对应 `permissions.allow`（见 `cli/06-permissions.md`）。

## MCP 工具

可配置自有 MCP 服务扩展能力，也可连接第三方 MCP 应用市场一键安装。
详见 `ide/10-mcp.md`。

## 🎯 与本项目的关系

| 本项目诉求 | Agent 模式对应机制 |
|---|---|
| 需求→用例的多步流程 | 待办事项计划（但复杂的应走 Quest Spec 驱动） |
| 生成用例后要人工把关 | 「已应用 → 等待审阅」+ 逐处接受/拒绝 |
| 生成跑偏了要全撤 | **Revert 按钮**（比手动 git checkout 干净） |
| 脚本反复确认很烦 | 设置 → 智能会话 → 自动执行允许列表 |
