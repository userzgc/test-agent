# 知识卡片 Knowledge Cards（Qoder IDE）

> 来源：https://docs.qoder.com/zh/user-guide/knowledge-engine/knowledge-cards

与 Repo Wiki **同步生成**，是从代码中提炼的高密度知识单元，
以 **Agent 易于直接消费的形式**存储，并**在每次 commit 过程中持续追踪代码变更**保持实时性。

## 三种卡片类型

| 类型 | 内容 | 作用 |
|---|---|---|
| **架构文档** | 模块整体设计思路、服务依赖关系、关键决策 | Agent 不用逐行读代码就能理解系统全貌 |
| **代码规约（Spec）** | 编码标准、命名规范、接口约定、业务逻辑约束 | Agent 生成代码时**自动对齐团队规范** |
| **技术栈** | 项目所用框架、库及版本信息 | 引入新依赖或生成代码时做出符合当前技术环境的决策 |

## 生成建议

**优先在主分支（`main`/`master`）和团队常用开发分支上生成**，以覆盖核心业务逻辑和代码结构。
生成过程中已完成的卡片可实时预览，无需等全部完成。

## 修改已生成的知识

在输入框用 **`/knowledge`** 命令人工干预修改：输入指令描述期望变更，
**或配合上传本地文件作为参考**，即可更新知识卡片内容。

> ⭐ 这是「人工纠正 Agent 认知」的官方入口。本项目 `docs/lessons-learned.md`
> 这类手写踩坑文档，正确做法是通过 `/knowledge` 写进知识卡片（或让 Memory 自动沉淀），
> 而不是留在一个没人保证会被读到的 md 里。

## 存储与共享

- 本地生成时自动保存到仓库的 **`.qoder/repowiki`** 目录，**可提交推送到远程分支**，
  团队成员 `git pull` 即可获取——无需额外配置
- **多语言**：生成时可选首选语言（English / 中文），系统为每种语言创建独立子目录（`zh/`、`en/`）
- **团队自动共享**：管理员在 Web 控制台开启「知识中心」开关后，任何成员生成的卡片自动同步至团队；
  其他成员打开相同仓库的相同分支点「生成」即自动获取团队最新知识
  ⚠️ **自动团队共享仅 Teams 版本支持**，其余情况用 Git 同步

## 计费

生成和更新**正常消耗 Credits**，可在 [用量详情-Credits](https://qoder.com/account/usage) 查看消耗记录。

## 🔁 与当前项目的关系

当前项目 `.qoder/repowiki/knowledge/zh/` 下已有自动生成的知识模块（4 个模块 × 5 篇），
正是这套机制的产物——**这是本项目唯一真正在生效的 Qoder 资产**。

但内容方向偏「代码架构」，而本项目是**文档/流程仓库**。
改进路径见 `ide/07-knowledge-engine.md` 的 `wiki_plan.yaml` 一节：
用 `template: product_requirement` + `documents` 白名单 + `notes` 把生成方向掰回「测试工作流说明书」。
