# 自定义指令 Custom Commands（Qoder IDE）

> 来源：https://docs.qoder.com/zh/user-guide/commands

把常用提示词、固定流程、项目约定封装为可复用命令。对话框输入 `/` 浏览、筛选、调用。

## 作用范围

| 特性 | 用户级 | 项目级 |
|---|---|---|
| **作用范围** | 当前用户的所有项目 | 仅当前项目根目录及其子目录 |
| **存储路径** | macOS/Linux `~/.qoder/commands/`<br>Windows `C:\Users\<user>\.qoder\commands\` | `<项目根目录>/.qoder/commands/` |
| **目录组织** | 支持按文件夹分类 | 支持按文件夹分类 |
| **共享方式** | 仅当前用户 | **可通过 Git 与团队共享** |

- ⚠️ 用户级指令**不支持跨设备同步**，需手动迁移配置文件
- 创建项目级指令前必须先打开目标项目
- 同名的用户级/项目级指令并存时，列表会附带**作用范围标识**区分

## 创建方式

1. 设置 → 指令页面 → 「添加」；或对话框输入 `/` → 底部「添加指令」
2. 顶部搜索栏输入**唯一指令名称**（如 `gen-test`）→ 回车
3. 名称规则：
   - 仅支持**小写字母、数字、连字符 `-`、下划线 `_`**
   - 不能为空
   - 长度建议 ≤ 100 字符
   - 同一作用范围下不能重名
4. 选择类型（用户级 / 项目级，未打开项目则无法创建项目级）
5. 填写指令说明 + 正文（开头写简短用途描述，正文写完整提示词或操作步骤）
6. 保存后回到会话，输入 `/` 即可看到

> ⚠️ **正文为空或仅保留默认占位内容的指令不会出现在可用列表中。**

## 刷新行为

新增/修改/删除指令文件后列表按最新状态刷新——新增出现新选项、修改后续使用新内容、删除后消失。

维护建议：按用途放子目录、填清晰描述便于搜索、定期清理旧指令。

## 官方 5 个示例指令

| 指令 | 用途 |
|---|---|
| `/code-inspect` | 源代码系统化评估框架：技术实现 / 开发标准 / 风险管理 / 维护方面 四大领域 checklist |
| `/security-check` | 安全态势检查：应用安全 / 认证系统 / 数据保护 / 系统架构 |
| `/create-pr` | 标准化提交流程：代码质量保证 → 变更文档 → 测试验证 → 提交要求 → 合并后计划 |
| `/project-test` | 执行测试套件并解决问题：环境设置 → 测试执行 → 问题解决 + 验证矩阵 |
| `/gen-agents-md` | 生成结构化 `agents.md` 定义 AI 代理规范 |

示例的共同结构是「## 概述 + ## 分阶段步骤 + ## checklist（`- [ ]` 勾选项）」。

## 🔁 与当前项目的关系

当前项目 `.trae/` 下**没有 commands 这一层**——Kiro/Trae 血统里没有对应概念。
但本项目大量的「固定流程」其实更适合做成 Command 而不是 Skill：

| 当前放在哪 | 更合适的载体 | 理由 |
|---|---|---|
| `.trae/skills/*/SKILL.md` 里的「照着这个流程走一遍」类内容 | **项目级 Command** | 由用户显式 `/xxx` 触发，确定性高，不依赖模型判断是否该加载 |
| `.trae/skills/*/SKILL.md` 里的「遇到 XX 场景时应该怎么做」类知识 | **Skill** | 靠 `description` 让模型自主判断加载时机 |
| 「每次都必须遵守」的约定 | **Rules**（`trigger: always_on`） | 无条件注入 |

⭐ 这一层区分是当前项目 9 个 skill 迁移时应该做的取舍：
**显式流程 → Command，条件知识 → Skill**。全塞进 Skill 会导致模型该加载时不加载。
