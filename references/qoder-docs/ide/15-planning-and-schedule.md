# Planning 规划智能体 与 定时任务（Qoder IDE）

> 来源：/zh/user-guide/chat/plan-agent + /zh/user-guide/quest/scheduled-tasks

## Planning（规划智能体）

让智能体在修改代码或执行命令**之前**先产出一份实施方案与计划。
**已内置于智能体模式，无需单独配置。**

### 两种调用方式

| 方式 | 触发 |
|---|---|
| **自动调用** | 智能体模式根据请求智能判断何时需要规划 |
| **显式调用** | **`/plan`** 命令 |

### 适用场景

推荐启用：涉及多个模块/文件的**复杂功能**；预期经历**多轮迭代**（设计、实现、测试、清理）。
小改动（拼写修正、变量重命名）直接用智能体执行更省时间。

### 流程

1. **描述任务** —— 建议包含：变更目标或要实现的功能、**限制条件**（如「不能破坏现有 API」）、可选提及重要文件/模块路径
2. **生成计划** —— 含**目标、技术方案、技术栈、实施计划**。
   ⚠️ **此阶段不修改任何文件、不执行任何命令**，产出仅是可审阅的计划
3. **审阅并调整** —— 可直接编辑，也可用自然语言协作调整（「最后加一步更新文档」）
4. **启动执行** —— 待办事项状态在聊天底部实时更新（未开始/进行中/已完成）。
   终端命令或 MCP 调用可能仍需手动确认
5. **执行中调整** —— 可暂停、说明新要求、让 Qoder 更新计划后继续。
   阻塞性问题（测试失败、依赖缺失）会在对话中明确指出并规划下一步
6. **收尾与回顾** —— 可按步骤总结每个 To-do 具体改了哪些文件

### 最佳实践

- **像给同事派任务那样写第一个提示词**：说明范围、限制条件和**验收标准**
- 高风险任务（重构、接口调整、核心路径改动）默认开启 Planning
- 第一版计划不理想就让它调整（「更关注测试部分」「尽量减少对公共接口的改动」）
- **保持每一步足够小**：一个好的待办事项应该能在一个较小的 diff 中看清影响范围

> Planning 与 Quest 的 Spec 驱动是两套东西：Planning 在**普通对话的 Agent 模式**里，
> Spec 驱动在 **Quest 视窗**里且产出可下载的结构化 Spec 文档 + 批注能力。
> Experts 模式**内置了 Planning 能力**，执行前会先生成实施方案。

## 定时任务

### 两种创建方式

| 方式 | 示例 |
|---|---|
| **命令触发** | `/schedule 今晚 10 点，为我今天改动的代码补齐测试` |
| **自然语言触发** | 「帮我今晚重构今天修改过的代码，提升可读性」——Quest 识别意图后确认缺失信息并创建 |

创建成功后会话流出现定时任务卡片，点「编辑」可调整。到时间自动执行，过程和结果出现在对应会话中。

> ⚠️ **必须确保 Qoder IDE 在计划执行时间处于运行状态。**
> 开启「保持系统唤醒」后，Qoder 会在任务时间前阻止系统休眠。

### 编辑表单字段

**任务名称** / **计划时间** / **任务指令**（执行时使用的完整 prompt）/ **模型选择**（默认同当前会话）/ **Goal 开关**

### 查找与管理

- **左边栏时钟图标**：含待执行定时任务的会话在历史列表中显示时钟标记；全部执行完或删除后图标消失
- **右侧概要「定时任务」板块**：列出所有任务，点击跳转编辑表单
- **一个会话支持多个定时任务**，独立管理互不影响

### 从 Spec 转定时任务

Spec 驱动完成需求澄清与 Spec 生成后，在 **Spec 卡片的 build on 区域点「设置定时」**。

### 最佳实践

- **任务指令写清楚**：定时执行时你不在场，Quest 完全依赖任务指令工作。
  **像写给同事的交接说明一样**，把范围、重点和约束写明确
- **Goal + 定时任务组合**：「提升测试覆盖率到 80%」这类需持续迭代的目标，开 Goal 设夜间定时效果最佳

### 🎯 本项目可用场景

| 场景 | 做法 |
|---|---|
| 需求文档更新后自动重跑用例生成 | `/schedule` + 明确指令（指定输入文档路径、输出 XMind 路径、用例条数下限） |
| 接口清单变更后自动核对用例覆盖 | 夜间定时 + Goal 模式迭代到覆盖率达标 |
| 批量补全历史用例的缺失字段 | Goal + 定时，避免占用白天交互时间 |
