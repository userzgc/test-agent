# 输出风格（Qoder CLI）

> 来源：https://docs.qoder.com/zh/cli/output-styles

调整回复的**语气、详略与结构**。
⚠️ 只在系统提示之上**叠加**说明，**不改变 Qoder 的核心身份与安全约束**，无法替换或绕过内置行为准则。

## 设置方式

顶层配置项 `outputStyle`（也兼容 `general.outputStyle`，**两处都配时顶层为准**）：

```json
{ "outputStyle": "concise" }
```
**修改后需重启。**

临时使用（**仅本次会话，优先级高于配置项，无需重启**）：
```shell
qoder --output-style concise
```

不设置或设为默认风格 → 使用内置默认表达方式，不叠加任何风格。

## 来源与优先级（后覆盖前）

1. **内置风格**
2. **插件提供的风格**
3. **用户级风格**
4. **项目级风格**

即项目级 > 用户级 > 插件 > 内置。

> ⚠️ 某些插件可声明「**强制风格**」，存在时**优先于 `outputStyle` 指定的风格**；
> 多个强制风格时第一个生效并记录提示。

## 自定义

放在指定目录下的 `.md` 文件，一个文件一个风格：

| 层级 | 目录 |
|---|---|
| 用户级 | `~/.qoder/output-styles/` |
| 项目级 | `<项目>/.qoder/output-styles/` |

**正文就是叠加到系统提示中的风格说明**：

```markdown
---
name: concise-cn
description: 简洁的中文回复风格
---

回复尽量简短，先给结论再给理由。
避免重复用户已知的信息，代码示例只保留关键部分。
```

| frontmatter | 必填 | 说明 |
|---|---|---|
| `name` | 否 | 缺省时用文件名（去掉 `.md`） |
| `description` | 否 | 缺省时取正文第一个非标题行 |

插件提供的风格引用时带前缀：`插件名:风格名`。

### 编写建议

- **聚焦表达方式**（语气、详略、结构），不是任务逻辑
- **保持简洁** —— 会叠加到系统提示中，过长占用上下文
- 不要试图覆盖安全约束

## 与其他机制的分工

| 机制 | 管什么 |
|---|---|
| `language` | 回复使用的**语言** |
| `outputStyle` | **怎么表达** |
| `AGENTS.md` / rules | **在这个项目里怎么做事**（项目约定） |
| 界面设置（主题、状态栏） | **显示层** |

## 🎯 对本项目的用法

用户明确表达过的偏好（「不看 md 文档，要直出 XMind」「不要写踩坑记录要防复发机制」）
属于**工作方式约定**，应该进 `rules`，**不是 outputStyle**。

真正适合 outputStyle 的是：「先给结论再给理由」「不要罗列不打算采纳的方案」这类表达偏好。
可以在 `<项目>/.qoder/output-styles/` 下写一个项目风格文件固化下来。
