# 规则（Rules）

> 来源：https://docs.trae.cn/ide/rules

## 是什么
规则用于规范 AI 行为，会话开始时自动注入并持续占用上下文窗口。

## 规则类型
| 类型 | 文件 | 作用域 | 适合 |
|------|------|--------|------|
| 个人规则 | `.trae/rules/user_rules.md` | 项目级生效 | 个人习惯：注释语言、代码风格 |
| 项目规则 | `.trae/rules/project_rules.md` | 项目级生效 | 技术栈约束、架构规范、安全要求 |

## 按路径生效
规则文件支持 `paths` frontmatter，只在处理匹配路径的文件时触发：

```markdown
---
paths:
  - "src/server/api/**/*.ts"
---
# API 约定
- handler 必须做输入校验
- 错误返回统一结构 { data, error }
```

## 优先级
项目规则 > 用户规则 > 默认行为

## 使用
设置 > Rules > 对应区域 + 创建，自动在 `.trae/rules/` 下创建文件。

## 规则不生效的常见原因
1. **措辞弱** — "可能""尽量"等会降低规则强度，用"必须""禁止"
2. **过于宽泛** — 太抽象的规则难执行，要具体
3. **路径错误** — `paths` 写错不触发
4. **作用域混淆** — 个人规则不会跨项目生效，需在每个项目分别配置

## 最佳实践
- 写具体而非抽象："所有 handler 必须做输入校验"优于"注意安全"
- 用肯定句：写"必须做什么"比"禁止不做什么"更有效
- 分路径配置：不同目录不同规则，避免无关噪音
