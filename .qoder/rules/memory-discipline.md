# 记忆纪律

原 `.trae/skills/memory-keeping/SKILL.md` 的方法论保留，**落点改为 Qoder 原生记忆**。

## 为什么换落点

原方案把记忆写进 `docs/memory/decisions.md` + `docs/memory/index.md`，靠 SessionStart hook
读索引带进上下文。这套在 Qoder 下**完全失效**：hook 不触发，`docs/` 下的文件没有任何
机制保证会被读到。

原 SKILL.md 自己写明了硬约束：「IDE 聊天记录会被清除，且 Hook 无法感知对话内容」。
Qoder 的长期记忆直接解决这件事 —— 自动召回、跨会话、跨项目。

## 落点对照

| 内容 | `UpdateMemory` 的 category |
|---|---|
| 业务口径 / 判定规则（聚合、边界、降级这类容易做反的） | `important_decision_experience` |
| 踩坑、根因、修复方式 | `common_pitfalls_experience` |
| 我的理解被用户纠正 | `common_pitfalls_experience` |
| 项目环境 / 目录结构 / 配置位置 | `project_environment_configuration` |
| 用户的工作方式约束（如「多动作要给选择框」） | `user_behavior` |
| 一个需求对齐完成后的整体结论 | `task_summary_experience` |

`docs/lessons-learned.md` **保留**，但降级为「给人翻的历史台账」，不再是唯一落点。
只写它 = 等于没记。

## 必须记

- 需求方**口述澄清**的业务口径 —— 文档里没写、只在对话里说过的
- 聚合 / 边界 / 降级这类「实现容易做反」的口径
- 我的理解**被用户纠正过** —— 写清错在哪、正确是什么
- 已登记但**未闭环**的待确认问题
- 发现的产品风险 / 缺陷线索

## 不要记

- 需求文档里已写清楚的内容（写来源引用即可，别复制原文）
- 一次性的调试过程、闲聊、探索性提问
- 已经记过的同一条（**先 `SearchMemory` 查，有就 update，不要新建重复条目**）
- 凭据、密码、token —— **任何情况都不记**，包括用户主动要求时

## 写入时机

1. **用户说触发词**（记一下 / 存档 / 记住这个 / 沉淀一下）→ 立即写入并告知落在哪
2. **我的理解被纠正的当场** → 立即写，不等会话结束
3. **一个需求的对齐阶段结束时** → 把该需求确认的全部口径整理后写入

注意：现在**没有 hook 会提醒我**（`.trae/hooks/` 在 Qoder 下不触发，且本项目未配 hook）。
所以写入完全靠当场自觉，没有兜底机制。

## 复用纪律（记忆的价值全在这一步）

新需求启动时先 `SearchMemory` 查有无同类。命中之后：

- **已确认的口径不要再问用户一遍**
- 引用时**标注确认日期**，并提示用户确认是否仍然有效 —— 业务口径会变，不能当永久事实用
- 与当前代码 / 配置冲突时，**以当前代码为准**，并回头修正那条记忆

## 禁止

- ❌ 把记忆当对话逐字稿，大段复制原文
- ❌ 同一条口径记成多条（先查再写）
- ❌ 直接拿记忆里的口径当事实用，却不告知来源和日期
- ❌ 每次会话都记一条，把记忆淹在噪声里
