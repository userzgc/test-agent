# 测试用例编写规范

蒸馏自 `.trae/skills/test-case-writing/SKILL.md`（已失效，仅作历史原料）。

## 输出格式：XMind 唯一默认

**直接输出 `.xmind` 文件。不写 MD 用例文档。**

需要其他格式（Excel / CSV / JSON / Markdown 表格）时，由用户明确指定后才切换。

> ⚠️ 原 SKILL.md 里同时存在「默认使用 Markdown」和「不再写 MD 用例文档」两句相反的话 ——
> 这是 MD 用例反复复发的根因之一。此处消歧：**XMind 是唯一默认**。

## 场景树结构（5 层）

```
根节点（项目名）
├── 1.大场景-正向
│   └── 小场景（一句话，不带 S1/S2 编号）
│       ├── 操作/数据（一句话）
│       └── 预期（一句话，含具体字段与数值）
├── 2.大场景-异常边界
└── N.兼容回归
```

**不要**用「前置条件 / 测试数据 / 步骤 / 预期结果」字段头。
**扁平化**：每个节点只放一句关键信息，多步骤拆成多个平行子节点，不用 `<br>` 合并。

## 大场景划分：业务流程横向 + 正向/异常纵向

参考划分（买A赠B 二期实例）：

| 大场景 | 包含 |
|---|---|
| 1.后台配置-正向 | 主品组合配置 / 赠品配置 / 赠品选择器筛选 |
| 2.后台配置-异常边界 | 非随心配拦截 / freeGroup 拦截 / 进行中编辑限制 |
| 3.C端算价-正向 | 门槛达成 / 多组判定 / 周边算价 / 专享价同享 |
| 4.C端算价-异常边界 | 未达门槛 / 取消回滚 / 库存不足 / 并发 |
| 5.C端展示 | 按钮文案 / 折叠 / 寄存券切换 / 周边展示 / 图片兜底 |
| 6.资损防控 | 补贴基数 / 不超优惠 / freeGroup / subsidyCap |
| 7.分账结算-下单 | 6 种模式 × {普通, 周边} |
| 8.分账结算-退款 | 6 种模式冲正 + 部分退款 |
| 9.兼容回归 | 存量活动 / 寄存券 / 非买赠活动 |

## 节点编写规则

1. 大场景节点：`数字.业务名-正向/异常边界`
2. 小场景节点：一句话描述，**不带 S1/S2 编号**
3. 子节点：操作/数据/预期混合，每条一句话
4. **数值必须具体**：写 `50元` 不写「某金额」；写 `productType=12` 不写「周边商品类型」

### 反例

```
❌ S1 【P0 正向】单活动商品 + 单组 selectQuantity=1
   - 前置条件: 后台已登录
   - 测试数据: 主商品：随心配套餐A
   - 步骤: 1.选主品 2.配置 3.保存
   - 预期结果: 保存成功
```

### 正例

```
✅ 单组1件（等价原买1赠1）
   - 主商品：随心配套餐A（1组1个饮品）
   - 保存成功，comboGroups=1组、selectQuantity=1
```

## 覆盖要求

| 场景类型 | 优先级 |
|---|---|
| 正向 | P0 |
| 完整生命周期（下单→发券→退款→回收→再下单） | P0 |
| 并发（涉及库存/锁） | P0 |
| 边界 / 异常 | P1 |
| 幂等（涉及 MQ 重复消费） | P1 |

需求不完整时，**标出假设和缺口**，不要静默填空。

## 不写的内容

- ❌ UI 点击步骤（「点击XX按钮→跳转XX页面」）
- ❌ 底层实现细节（「DB写入XX字段」「缓存清除」）
- ❌ 独立的「前置条件」节点（融入测试点标题）
- ❌ 为凑数量写重复或低价值用例

## 冒烟用例

- 从完整版抽核心 P0，约 **15–20 个**
- 沿用相同大场景结构，每场景只留 1–2 个关键子节点
- 模块可合并（如 `1.后台配置` / `2.C端算价`，不分正向/异常）

## 工具链
